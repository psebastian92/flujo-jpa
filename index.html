Recorrido de un pedido

Qué pasa, capa por capa, cuando en el proyecto de música alguien lista, da de alta, edita o borra un artista. Primero, dónde corre cada cosa:

Computadora del usuarioNavegador o Bruno

Piden páginas al servidor. El navegador dibuja el HTML que recibe; Bruno lo muestra crudo, con el código de estado. Ninguno tiene los datos ni el código Java.

Servidor (Tomcat)Servlet + JSP = capa de presentación

El Servlet recibe el pedido y el JSP fabrica el HTML. Los dos corren en el servidor, junto con la lógica y la persistencia.

Servidor de base de datosMySQL

Guarda las tablas. Solo habla con Hibernate, por JDBC.

Cliente: navegador o Bruno Presentación: Servlet y JSP Lógica Persistencia JPA y base

Los códigos que vas a ver en Bruno

    

      

        
CódigoQué significaCuándo aparece

        
          
200 OKEl servidor respondió bien.Al listar o al abrir el formulario de edición.

          
302 FoundRedirección: "andá a otra URL".Después de un alta, una edición o una baja, y también cuando hay un error que se maneja bien.

          
404 Not FoundNo existe nada en esa URL.El Servlet no existe o el nombre no coincide con el @WebServlet.

          
500 Internal Server ErrorUna excepción que nadie atrapó.Nunca debería aparecer: hay que agregar el try-catch o la validación que falta.

        
      

    


    

      
forwardEl Servlet le pasa los datos a un JSP para mostrar una pantalla. Se usa al leer.

      
sendRedirectEl Servlet le dice al navegador "andá al listado". Se usa después de guardar, para que F5 no repita el alta.

      
Cada capa habla solo con la de abajoEl Servlet nunca toca el EntityManager. El JSP nunca llama a la lógica.
